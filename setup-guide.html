Why this strategy

Thirteen candidates were tested on 5,000 4h bars of this exact instrument, split chronologically. SMA 40/100 was the only one positive in both halves — +43.9% train, +8.1% test. It also independently won the twenty-strategy search across forex and stocks in run_search.py. Two unrelated datasets, same winner.

Read this before you get excited

The test half was a BTC downtrend — buy-and-hold lost 43%. In a downtrend anything that sits in cash "beats the benchmark", and twelve of thirteen strategies did. That number means nothing.

Being positive in both halves is the only part that survives, and it rests on 20 trades.

Demo carries three symbols — BTC, ETH and XRP. There is no gold, so the XAUUSD work in this repo cannot be demo-traded here.

5

Only then, demo orders

Real order flow against Bitget's simulator. Still fake money.

Log into Bitget, switch to Demo Trading, then open API Key Management from inside demo mode. Give the key trade permission and leave withdrawals disabled.

export BITGET_API_KEY=...
export BITGET_API_SECRET=...
export BITGET_API_PASSPHRASE=...
export BITGET_LIVE_CONFIRM="I ACCEPT LIVE TRADING RISK"

.venv/bin/python -u bitget_bot.py --demo --live

--live here means "send orders", not "real money" — --demo keeps it on the simulator.

Unverified

The demo order path could not be tested without credentials. The code sends the paptrading: 1 header with the S-prefixed symbols, which matches Bitget's documentation — but that documentation contradicts itself on whether demo accepts a live API key. If orders come back rejected, regenerate the key from inside Demo mode.

What to watch for

SignMeaning
EXCESS fallingWorking as expected. This is what costs look like.
EXCESS positiveAfter 4+ weeks: interesting. Not yet evidence.
STALEFeed stalled. The bot correctly held instead of trading a stale price.
REFUSINGA gate did its job. Read the line.
Many TRADEs/dayWrong timeframe. Costs will eat it.

Never restart the bot to "reset" a bad run. The journal anchors the benchmark on the first decision precisely so restarts cannot flatter the result.

Before real money ever

01Paper for weeks. Compare EXCESS against buy-and-hold.
02Demo orders for weeks. Confirms fills, rejections, reconnects.
03Live at a size where total loss is tuition.
04Live properly — only if 03 matched 02.

Going live requires --live without --demo, plus the confirmation phrase, plus keys. Three deliberate acts. Nothing in this repo has earned step 03.

About twenty strategies were tested across stocks, forex, gold, crypto and indices. Zero beat buy-and-hold. Every profitable backtest here was eventually traced to a bug — a frozen benchmark, a 24/7 annualisation on a market open 5.5 hours a day, a null distribution centred wrongly, a strategy that took zero trades while reporting 0.00%.

The most likely outcome of running this is that EXCESS stays negative and you learn that for free. That is a good trade.
